# Voca Quiz

한글 뜻을 보고 **제한 시간 안에 영단어 전체를 타이핑**하는 암기 앱.
객관식이 아니라 직접 철자를 쳐야 하므로 "뜻은 아는데 스펠링이 안 나오는" 상태를 없애는 데 초점을 맞췄다.

```
       통합하다
   s _ n t _ _ _ _ _ e        ← 첫 글자 + 난이도에 따라 몇 글자 공개
   [ synthesize        ]      ← 전체 단어를 타이핑
   ████████░░░░░░  6.2s
```

## 지금 되는 것

| 기능 | 설명 |
| --- | --- |
| 단어 등록 | 엑셀에서 두 열을 복사해 붙여넣기만 하면 자동 분류. `.csv` / `.txt` 파일도 가능 |
| 난이도 | 첫 글자는 항상 공개 + 글자 수의 0~40%를 **흩어서** 추가 공개 |
| 제한 시간 | 단어당 3~120초, 1초 단위 조절 |
| 문제 수 | 기본 50개, 단어장(덱)별로 범위 지정 |
| 출제 전략 | 취약 단어 우선(기본) / 무작위 / 등록 순서 |
| 정답 판정 | 대소문자·공백 무시, 한 글자 차이는 "아깝다"로 구분 |
| 복습 | 틀리면 정답 따라 치기 + 세션 뒤쪽 재출제 + 결과 화면에서 오답만 재도전 |
| 기록 | 단어별 정답률·연속 정답, 일별 학습 기록(연속 학습일) |
| 계정(선택) | Google 로그인 시 단어장이 기기 간 자동 동기화. 로그인 안 해도 전부 동작(게스트 모드) |
| 발음(선택) | Merriam-Webster 성우 녹음(미국식) + 발음기호. 채점 순간 자동 재생 |

## 단어 등록 형식

붙여넣기 파서는 아래를 전부 알아서 처리한다. 한 줄에 한 단어.

```
synthesize	통합하다, 종합하다      ← 엑셀 복붙 (탭)
mitigate 완화하다                   ← 구분자 없이 공백만
12. prolific - 다작하는             ← 앞 번호·하이픈
"acute","극심한"                    ← CSV
분명한  apparent                    ← 한글이 앞에 와도 OK
give up	포기하다                    ← 공백 포함 숙어
```

붙여넣으면 바로 등록되지 않고 **검수 표**가 뜬다. 행마다 en/ko를 직접 고칠 수 있고, 이미 등록된
단어는 회색으로 흐려지며, 자동 보정이 들어간 행은 노란 배지로 표시된다. 체크한 행만 등록된다.

> **엑셀 `.xlsx` 파일을 직접 여는 기능은 넣지 않았다.** 엑셀에서 셀을 복사하면 탭 구분 텍스트가
> 그대로 클립보드에 들어가므로 붙여넣기로 충분하고, `.xlsx` 파싱 라이브러리를 하나 덜 쓰는 쪽이
> 번들 크기와 보안 면에서 낫다. 파일로 넣고 싶으면 엑셀에서 `CSV로 저장` 후 불러오기.

### 종이 단어장 옮기기

1. **먼저 확인** — 출판사가 단어 리스트를 엑셀/PDF로 배포하는 경우가 많고, Quizlet에 이미
   같은 책의 세트가 있을 확률도 높다. 공식 "내보내기"는 탭 구분 텍스트라 그대로 먹히고, 학습
   화면에서 그냥 긁어 복사해도(권한이 없어 내보내기가 안 될 때) 된다 — "단어" 줄 다음에
   "유의어, ..., 한글 뜻"이 섞인 줄이 와도 자동으로 합쳐서 유의어까지 뜻에 그대로 남긴다.
   OCR보다 훨씬 빠르고 오타가 없다.
2. **그래도 직접 찍어야 한다면** 폰 기본 OCR(구글 렌즈, iOS 텍스트 인식, 네이버 스마트렌즈)을
   쓴다. 인앱 OCR은 일부러 넣지 않았다 — 한글+영문이 섞인 인쇄물에서는 폰 기본 OCR이 브라우저
   OCR(Tesseract.js 등)보다 정확하고, 이미 폰에 있어 설치할 것도 없다.
   **팁: 영단어 줄과 뜻 줄을 따로 찍기보다, 한 행이 가로로 통째로 잡히게 찍어야 짝이 안 어긋난다.**
3. 인식된 텍스트를 그대로 복사해 붙여넣는다. `parseBulk`가 잡음을 먼저 정리한다:
   - 영단어만 있는 줄 바로 다음에 한글이 섞인 줄이 오면 한 줄로 합친다 — OCR이 두 열을 위아래로
     잘못 읽는 경우, 그리고 Quizlet 학습 화면처럼 "단어" 다음 줄에 "유의어, 한글 뜻"이 오는
     경우 둘 다 해당한다.
   - `Day 3`, `Chapter 12` 같은 표제 줄과 페이지 번호만 있는 줄은 제거한다.
   - `0↔o`, `1↔l`, `5↔s`, `|↔l` 같은 흔한 오인식을 알파벳 자리에서만 보정한다.
4. **검수 표에서 반드시 확인한다.** 자동 보정은 문자 하나 차이로 완전히 다른 단어를 만들 수도
   있다 — 특히 노란 배지가 붙은 행은 눈으로 한 번 더 봐야 한다. 파싱에 아예 실패한 줄도 표에
   빈 칸으로 올라오니 원문을 보고 직접 채우면 된다.

## 난이도가 동작하는 방식

- **첫 글자는 항상 공개한다.** 동의어가 많아 한글 뜻만으로는 답이 하나로 좁혀지지 않기 때문.
- 나머지는 `hintRatio` 비율만큼 공개하되, 남은 자리를 균등 구간으로 나눠 **구간마다 하나씩** 뽑는다.
  무작위로 뽑으면 공개 글자가 앞쪽에 몰려 힌트 가치가 떨어진다.
- 같은 단어라도 세션마다 시드가 달라져 **공개 위치가 바뀐다.** 위치 패턴 자체를 외우는 걸 막기 위함.

| 프리셋 | 비율 | `synthesize` (10글자) |
| --- | --- | --- |
| 쉬움 | 40% | `s _ n t _ _ _ _ _ e` |
| 보통 | 25% | `s _ _ t _ _ _ _ _ e` |
| 어려움 | 10% | `s _ _ _ _ _ _ _ _ _` |
| 지옥 | 0% | `s _ _ _ _ _ _ _ _ _` |

## 데이터 저장 & 계정 동기화

**localStorage가 항상 정본이다.** 로그인하지 않아도 모든 기능이 그대로 동작하고(게스트 모드),
Supabase는 그 위에 얹는 동기화 계층일 뿐이다. 오프라인(지하철 등)에서도 문제없이 써야 한다는
이 앱의 용도상, 네트워크가 핵심 기능을 막는 일은 없어야 한다는 원칙으로 짰다.

- 브라우저 데이터를 지우면 단어장이 날아가므로, 로그인을 안 쓸 거면 **단어장 관리 → JSON 백업**을
  가끔 눌러 두는 걸 권한다.
- 로그인하면 단어(등록/수정/삭제)가 기기 간 자동 동기화된다. **세션 기록(오늘 몇 문제 풀었는지 등)은
  아직 로컬에만 있다** — 단어장을 잃는 게 훨씬 치명적이라 그쪽부터 단단히 하고, 학습 기록 동기화는
  다음 단계로 미뤘다.
- 삭제는 실제로 지우지 않고 "삭제됨" 표시만 한다(소프트 삭제). 안 그러면 아직 동기화 못 한 다른
  기기가 다음 동기화 때 지운 단어를 되살려 버린다.

### 계정 연동 켜기 (선택)

1. [supabase.com](https://supabase.com)에서 무료 프로젝트를 만든다.
2. 프로젝트의 SQL Editor에 [`supabase/schema.sql`](supabase/schema.sql) 내용을 붙여넣고 실행한다
   (테이블·RLS 정책 생성, 1회성).
3. **Authentication → Providers → Google**에서 Google 로그인을 켠다. Google Cloud Console에서
   OAuth 클라이언트를 만들고, Supabase가 알려주는 콜백 URL(`https://<ref>.supabase.co/auth/v1/callback`)을
   승인된 리디렉션 URI로 등록한다.
4. **Project Settings → API**에서 `Project URL`과 `anon public` 키를 확인한다.
5. 로컬 개발: `.env.local.example`을 `.env.local`로 복사해 두 값을 채운다.
6. 배포(GitHub Pages): 저장소 **Settings → Secrets and variables → Actions**에 같은 이름으로
   `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 등록한다. `deploy.yml`이 빌드 시점에 주입한다.

둘 다 설정하지 않으면 앱은 자동으로 게스트 모드로만 빌드된다 — 계정 기능을 아직 안 쓸 거면
이 절을 그냥 건너뛰면 된다.

> Supabase 무료 프로젝트는 **7일간 API 요청이 없으면 자동 일시정지**된다. `keepalive.yml`이
> 매주 한 번 가볍게 핑을 보내 막아 주지만, 일시정지되더라도 오프라인 우선 설계 덕분에 앱 자체는
> 계속 동작한다(그냥 그 사이 다른 기기와의 동기화만 잠깐 멈춘다).

## 발음

**틀린 발음을 알려주느니 아무것도 안 알려주는 게 낫다**는 원칙으로 만들었다. 철자와 발음을
정확하게 외우는 게 이 앱의 목적이라, 어정쩡한 소리를 들려주면 기능이 있는 것이 오히려 해롭다.
그래서:

- **Merriam-Webster 성우가 실제로 녹음한 미국식 음원**만 쓴다. TOEFL이 미국식이라 목적에 맞고,
  Learner's Dictionary는 ESL 학습자용이라 **국제음성기호(IPA)** 를 함께 준다.
- **TTS(기계 합성) 대체를 하지 않는다.** 음원이 없으면 "발음 없음"이라고 밝힌다. 흔한 무료
  사전 API(Wiktionary 계열)도 쓰지 않는다 — 자원봉사자 녹음이라 영/미/호주 억양이 섞여 있다.
- **표제어가 정확히 일치할 때만** 발음을 붙인다. MW가 비슷한 철자를 추천해 와도 무시한다.
  엉뚱한 단어의 음원을 들려주는 게 가장 나쁜 실패라서, 애매하면 포기하는 쪽을 택했다.

조회 결과는 `pronunciations` 테이블에 **전 사용자 공유로 캐시**되므로 단어 하나당 평생 최대
2회만 MW를 부른다(무료 티어는 사전당 1000회/일). 음원 mp3는 우리 쪽에 복사하지 않고 MW CDN의
URL만 저장한다.

### 발음 켜기 (선택, 계정 연동이 먼저 되어 있어야 함)

1. [dictionaryapi.com](https://dictionaryapi.com)에 무료 가입하고 키 두 개를 신청한다 —
   **Learner's Dictionary**(주력, IPA 제공)와 **Collegiate Dictionary**(보조). 무료 티어가
   딱 2개까지 허용된다.
2. Edge Function을 배포하고 키를 등록한다:
   ```bash
   supabase functions deploy pronounce
   supabase secrets set MW_LEARNERS_KEY=... MW_COLLEGIATE_KEY=...
   ```

키를 등록하지 않으면 발음 버튼이 그냥 나타나지 않을 뿐, 나머지는 평소대로 동작한다.
API 키는 Edge Function 환경변수에만 있고 클라이언트 번들에는 절대 들어가지 않는다.

> **⚠️ MW 무료 키는 비상업 전용이다.** 개인 학습이나 친구와 공유하는 건 해당하지 않지만,
> 나중에 광고를 붙이거나 유료 앱으로 출시하려면 MW와 별도 계약이 필요하다.

## 로드맵

localStorage 스키마는 서버로 옮길 걸 염두에 두고 짰다 (`updatedAt`/소프트 삭제 기반 동기화).
`SessionResult.date`는 일별 기록이라 출석 기능이 바로 얹힌다.

- **완료 — 계정 & 단어 동기화**: Google 로그인 + Supabase, 기기 간 단어장 자동 동기화.
- **완료 — 발음**: Merriam-Webster 성우 녹음 + IPA. 위 "발음" 절 참고.
- **다음 — 세션 기록 동기화**: 지금은 단어만 동기화되고 일별 학습 기록은 기기 로컬에만 있다.
- **다음 — PWA**: 오프라인 설치형으로 먼저 내고, 필요하면 Capacitor로 스토어 배포.
- **이후 — 대결 방**: 최대 5명이 같은 50문제를 동시에 푸는 방 (Supabase Realtime).
  이때 `retypeOnMiss` / `requeueWrong`은 꺼야 한다 (개인 학습용 옵션이고, 대결에서는 모두가
  같은 문제 수를 같은 순서로 풀어야 공정하다). 마스킹 시드도 방 단위로 고정해 전원이 같은
  힌트를 보게 해야 한다.
- **이후 — 출석 & 프로필**: 연속 출석 5일마다 프로필 꾸미기 아이템 지급.
